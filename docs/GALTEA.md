# Galtea: what we did, and what it caught

Galtea is an evaluation platform: you describe what a product must do, it turns that into
specifications, and an AI judge scores your product's real answers against them. We used it as an
outside reviewer of the analyser — a second opinion that did not come from our own metrics.

**The headline: it found a real defect in under an hour, and we had not found it ourselves.**

## What was set up

| Thing | Value |
| --- | --- |
| Product | ContextGuard Social (the product was renamed to Unfold after these runs; the Galtea object keeps its name so the 200 traces stay attached) |
| Specifications | 22, generated by Galtea from a written description of what the product must do, refuse, and get right |
| Dataset | The 50-post evaluation set: 15 mirrored left/right pairs, 10 neutral posts, 5 injection twins |
| Metrics | 5 AI-as-judge metrics, one per guardrail, plus one of Galtea's own |
| Traces | 200 real pipeline runs against `openai/gpt-oss-120b` |

The product under test is the real thing. `backend/eval/galtea_run.py` wires `run_pipeline` in as
the agent, so Galtea calls the actual analyser for every test case — live search, live model — and
judges what comes back. Nothing is replayed from a file.

```bash
.venv/bin/python -m backend.eval.galtea_setup      # create and link the judge metrics
.venv/bin/python -m backend.eval.galtea_run        # run the pipeline against the version
.venv/bin/python -m backend.eval.galtea_run --status-only
```

## What it scored

197 of 200 test cases analysed cleanly. Mean score **0.92**.

| Metric | Score | n | What a miss means |
| --- | --- | --- | --- |
| verbatim-trigger-quotes-strict | **1.00** | 50 | A quoted span is not in the post, so the extension cannot highlight it |
| neutral-post-restraint | **0.98** | 50 | An informational post was flagged as persuasive |
| supplied-citations-only | **0.98** | 50 | A verdict asserts support no listed source provides |
| unknown-author-fallback | **0.80** | 50 | A biography was written for an account with no source |
| Evidence Source Integrity Check | 0.78 | 50 | Galtea's own metric: a cited URL does not support the claim |

## The defect it caught

**The analyser attaches a real organisation's biography to an invented account that happens to
share its name.** Ten of fifty posts failed `unknown-author-fallback`, and the judge's reason on
the clearest one:

> The SPEAKER line describes Patriot Front as an American white supremacist group and provides
> additional background information, which constitutes invented speaker context.

Every author in the evaluation set is fictional, so the correct answer is always the exact words
"Unknown author". But `Patriot Front` is also a real organisation with a real Wikipedia page, so
`wikipedia_summary()` found it, and the pipeline dutifully attached it. The lookup matches on the
scraped display name and only rejects explicit disambiguation pages — it never checks that the
page is about *this* account.

**Why this matters more than the score.** On the demo set it looks like a quirk of synthetic
data. On a real timeline it is the worst failure the product can make: a confident, sourced,
plausible description of the wrong person or group, rendered next to their post with a link. It
is exactly the defamation exposure that `docs/ANALYSIS.md` raised before any code was written,
arriving through a door we had not watched.

It is not fixed. The fix is a match check between the account and the page — handle in the
article, name equality, an entity-type test — and it is the first thing to do after the
deadline.

## What this cost us in accuracy, and what it did not

Galtea's own `Evidence Source Integrity Check` scored 0.78, which reads worse than it is: our own
`cited-only` metric measures whether a cited URL was in the retrieved evidence, and it is 1.00.
Galtea's judge asks a harder question — whether the cited page actually supports the claim — and
on synthetic posts about invented events, a real Reuters or Census page retrieved by search
usually does not. Both numbers are correct; they ask different questions. The disagreement is
worth keeping visible rather than explaining away.

## Two ways we used the platform

Galtea can be driven from either end, and both are wired:

- **`galtea_run.py` — Galtea judges.** It drives the loop, calls our pipeline per test case, and
  an AI judge scores the answer. This is what produced everything above.
- **`galtea_sync.py` — we judge.** It pushes scores our own metrics computed, as self-hosted
  metrics, so the platform holds the v0-versus-v1 guardrail comparison from `docs/EVAL.md`
  alongside Galtea's own verdicts.

The second exists because three of our eleven metrics are **pairwise** — symmetry between a
mirrored left/right pair is a statement about two posts, and no single-post judge can score it.
See `docs/EVAL.md` for how eleven run-level metrics became nine per-trace ones.

## Notes for anyone repeating this

Four platform behaviours that cost time, all now handled in the scripts:

1. **Specifications arrive without metrics.** `evaluations.run` resolves nothing for a
   specification that has no metric linked, so the first run called the agent zero times and
   reported success.
2. **A dataset links to one specification at a time.** Linking it to a second silently detaches
   the first. Each specification gets its own copy of the 50 posts; a dataset created from a file
   runs no generator and costs no generation credits.
3. **A specification carries its own `testType`.** The injection specification is `RED_TEAMING`
   and refuses a `QUALITY` dataset, which is why injection resistance is the one guardrail still
   unwired here — it is measured in `docs/EVAL.md` instead.
4. **The SDK picks the agent's argument shape from the first parameter's annotation, by
   identity.** `from __future__ import annotations` stringifies it and silently downgrades a
   typed agent to chat history. `galtea_run.py` is the one module in this repo without that
   import.

And one of our own making, worth stating because it is the easy mistake: the first judge prompt
awarded 1.0 when no rhetorical signals were listed, so 25 crashed traces scored full marks and
every evaluation came back at exactly 1.00. **A metric that cannot tell a good answer from a
crashed one is not measuring anything.** Every judge now scores 0 when the answer is not an
analysis.
